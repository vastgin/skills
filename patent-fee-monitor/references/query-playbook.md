# 采集剧本（Step 3）

> **优先走 v5 脚本（2026-10-10 实测，单条 2–9 秒）**
>
> ```sh
> PY=.../python3
> $PY references/scripts/collect_one.py <申请号> --outdir out   # 单条，一条一次调用
> $PY references/scripts/collect_batch.py list.txt --outdir out # 批量，逐行打印进度
> $PY references/scripts/push_mcp.py --dir out                  # 上报
> ```
>
> 它已内置本文全部判定逻辑（三态、串扰校验、数量上限、状态枚举、feeYear 兜底、
> 类型位推导），并把「点击→等渲染→提取」压进一次 `bsk evaluate`。
> 下面的逐步剧本是**手工兜底路径**：脚本不可用、站点改版需重新探路、或要排查异常时才用。
> 关键差异：当前详情页是 **Element UI**（`role=treeitem` / `.el-tree-node__content`），
> 不是 Quasar；且树**按需渲染**，著录必须在切「费用信息」前取。

站点：CNIPA「案件查询（公众）」。用 **BrowserSkill**（`bsk`）驱动真实页面走 DOM，**不直连内部 API**。定位一律**不依赖页面随机生成的元素 id**（输入框 id 形如 `f_<uuid>`，运行时变化），改用标签文字 / role / title 属性。

## 导航路径

1. 打开 `https://cpquery.cponline.cnipa.gov.cn/chinesepatent/index`，等左侧 tab 面板渲染。
2. 点左侧竖排 tab **「案件查询」**（`role=tab` 或含该文字的 tab 元素）。
3. 查询身份选 **「公众」** radio（`role=radio[name="公众"]`），确认 `aria-checked="true"`（未选中只警告不阻断）。
4. 查询身份确认「公众」后，**用「重置」清空表单**（精确匹配按钮文字，避免误点「查询历史」）。
   - 首次进入页面时表单本就是空的（输入框 `[empty]`、身份默认已选「公众」），首轮可不点；**批采续轮时要点一下重置**，把上一轮的申请号与结果列表清掉再录下一条。
   - **不要每轮重新导航（刷新）**：留在主页面点重置即可，比重载快也不打断会话；仅当重置按钮不可见（页面已不在入口页）时才 `navigate` 兜底。重置后若仍有残留值，再点一次。
5. 「申请号/专利号」输入框按标签文字定位（label 含「申请号/专利号：」）。**逐字符输入**申请号，每键间隔 40-160ms 随机；输入完回读断言其值等于申请号。
6. 点 **「查询」**，读结果总数「共查询到 N 条结果」。
   - **陷阱：入口页默认就带「共查询到 0 条结果」**，所以「点击没生效」与「真的查无此号」在页面上**长得一模一样**（快照与纯净入口页逐行相同，仅输入框值不同）。
   - 判定必须要求**正计数**（`共查询到 [1-9]`）；重试时要**重做点击**（必要时重录申请号），只重复观察无效。实测 `2016102476204` 因点击未生效被判未查到，仅重复观察 3 次仍是 0 条，把点击纳入重试后一次通过。
7. 有结果时校验首行申请号与输入一致（防串扰），点案件标题打开详情（新窗口/弹窗）。标题的可点击元素是 `span.title.hover_active`（非随机 id，可直接用 CSS 选择器点击），**详情在新标签页打开，读完必须关闭**（见下节）。
8. 详情页等待就绪后，左侧树点 **「费用信息」** 节点，等费用表渲染。
9. 读 **「应缴费信息」** 表（未缴年费）与 **「已缴费信息」** 表（已缴年费，只取年费类）——
   均按区块标题文字定位其容器内的 table；收据发文信息、冲红信息不采集。
10. 表格按**表头文字**映射列，列序变化不影响：`费用种类`、`应缴金额/金额`、`缴费截止日/截止日`、`费用状态`。

## 批处理工程约束（实测踩坑，批采前必读）

- **只复用一个标签页**：详情页是新开的标签页，**读完立即 `tab close <detail_tab_id>`**，否则每采一条漏一个——50 条会堆出 50 个标签页。做法是用 `--tab-id` 把 `navigate` / `click` / `observe` / `press` 全部**钉在同一张主标签页**上，详情页单独用 `tab list` 找出来（URL 含 `/detail/`）再关闭。
- **只操作 `scope=agent` 的标签页**：`tab list` 会同时列出**用户自己的标签页**（`scope=user`，含其业务系统、参考资料等）。关闭/借用前必须按 scope 过滤，**绝不碰用户标签页**。
- **不要每轮刷新页面**：批采时留在主页面，用 **「重置」** 清空表单后录下一条（比重载快、也不打断会话状态）；只有重置按钮不可见时才 `navigate` 兜底。
- **`navigate` 之后必须先观察一次**：元素引用（`@eN`）按页面快照分配，导航后旧引用全部失效，直接点击/输入会**静默落空**——表现为输入框仍为空、查询等于查空表单、结果恒为 0 条（曾整批 48 条全采空）。所以「导航 → `observe` → 取引用」是固定顺序。
- **输入后回读校验**：输入完立刻观察输入框并断言其值等于申请号；不一致则重新导航并重打一次，仍不一致才跳过并记为 `TYPEFAIL`。
  - 取值陷阱：空值行的形态是 `@eN textbox "…" [empty] placeholder="例如: 2010101995057"`，**行末的 `="…"` 是 placeholder 不是值**；必须先判 `[empty]` 再取值。
- **SPA 无浏览历史**：`navigate-back` 会报 `no previous history entry`，返回列表靠**重新导航入口页**，不要用后退。
- **shell 陷阱**：批量关标签页时，zsh **不对未加引号的变量做词分割**，`for id in $IDS` 会把整串当成一个参数（报 `invalid digit found in string`）。脚本用 `#!/bin/bash` 执行，或在 zsh 里写 `for id in ${=IDS}`。

## 逐条进度播报（硬性 —— 长任务可见性）

**禁止把整批采集塞进一次命令调用。** 单次调用期间输出被整体折叠，用户全程零感知（实测 50 条静默跑完，用户明确反馈「没感知」）。**必须一条一次调用**，每条完成即播报一行进度。

- 单条采集：`python3 references/scripts/collect_one.py <申请号> --outdir out` —— 脚本自己打印一行进度，直接转述即可。
- 批量：`collect_batch.py <清单> --start N`（**默认一批 10 条**，进度逐行打印）。有人看着时按批调用、逐批转述，不要一次静默跑完全部。
- 参考实现：`references/scripts/` 下的 `collect_one.py` / `collect_batch.py` / `push_mcp.py`（详见 `scripts/README.md`）。

**播报格式（逐字给用户，一条一行）**：

```
[12/50] ✓ 2021110632883 · 网络舆情监测方法… · 未缴2+已缴2 条 ¥5,600 · 年度 6–4
[13/50] ✗ 2021110766182 · 查无此申请号
[14/50] ⚠ 2021109480292 · RETRYABLE:详情页 NO_FEE_NODE
[15/50] ✓ 2021109850001 · 数据采集任务异常预警… · 未缴2+已缴2 条 ¥5,600
```

- **五要素**：序号/总数、状态符号、申请号、专利名（超 12 字截断加 `…`）、条数与金额（`未缴N+已缴M 条 ¥X`）。附加信息用 ` · ` 分隔。
- **状态符号**：`✓` 成功（含全已缴清 rows=0）｜`✗` 未查到/未授权｜`⚠` 费用读取失败/异常｜`↻` 重试后成功。
- **失败也必须播报**，禁止静默 `continue`——静默跳过是「没感知」的第二大来源。
- 每 10 条追加一行累计小结：`—— 已采 10/50 · 累计 132 条 / ¥980,400 · 失败 1 ——`。
- 单条约 **2–9s**（冷启动首访或触发重试时可达 15–20s），播报节奏天然合适；不要为求快而合并成静默批处理。

## 弹窗与遮罩（实测踩坑，TYPEFAIL 先查这里）

- **登录成功回到入口页会再次弹「使用说明」公告弹窗**（只有一个「确定」按钮）。不点掉它，`fill` 会报 `the page moved focus away from the fill target`，表现为 TYPEFAIL（快照里输入框永远 `[empty]`）。识别特征：observe 里 `L1 modal cover=100%`，但 aria 快照里看不到弹窗内容。处置：`bsk click --selector ".q-dialog__inner button"`，再确认 `.q-dialog` 数量为 0。
- **`bsk request-help` 完成后会残留 `<browser-skill-overlay data-bsk-overlay-blocking>` 元素**，覆盖全屏并继续阻塞后续 fill/click。处置：`bsk evaluate "document.querySelectorAll('[data-bsk-overlay]').forEach(e=>e.remove())"`，再用 `elementFromPoint` 验证页面中心恢复为普通元素。
- 采集脚本的遮罩清理只认 `.q-loading*` / `.el-loading-mask`，**不覆盖**上述两类遮罩 —— 遇到 TYPEFAIL 先查这两项，再怀疑输入法或前端框架。

## 节奏与输入方式（硬性）

- **申请号直接填充，不逐字符敲**：用 `bsk fill @eN --value "<申请号>"`（默认先清空字段），秒级完成。逐字符敲 15 位要 1–2.4s，50 条白费近一分钟 —— 用户明确反馈「打得太慢了」。
  - **但填充后必须回读校验**：读输入框断言 `值 == 申请号`。Quasar 的 v-model 若没捕获 fill 派发的 input 事件，会静默失败（表现为查询 0 条）。
  - 校验不过 → 降级为逐字符重打，再校验一次（`collect_one.py` 用 `bsk fill` + 回读断言，已内置这条链）。
- 其余动作间停顿保持随机 **350–1200ms**，避免匀速的机器节奏。
- 每条走完再下一条，批内不并发；每批 ≤50 条，批间休息 ≥60s 并告知用户进度。
- 单条实测约 **2–9s**（查询 → 详情 → 费用表全流程；冷启动或触发重试时 15–20s），打字已非瓶颈。

## queryStatus 判定决策树

```
结果列表 0 条 ──► 复核：**重做「查询」点击**（必要时点重置重录申请号），最多 3 轮；仍为 0 才判 not_found（failReason="查无此申请号"，不重试）
　　│　（入口页默认就是「共查询到 0 条结果」，所以「点击没生效」与「真的查无」在页面上无法区分；只重复观察无效）
列表 > 0 条：
  ├─ 案件状态命中未授权关键词 ──► not_granted（不重试）
  ├─ 已授权 + 费用表有数据 ────► ok
  ├─ 已授权 + 费用表空/读取失败 → error + failReason="RETRYABLE:<页面级原因>"（当场重试2次，间隔随机3-5s）
  └─ 页面异常无法判定 ─────────► error（连续2次同因→停止采集，走 login-guide 掉线流程）
```

- 未授权关键词（命中任一即 not_granted）：`审中`、`实审`、`实质审查`、`公开`、`驳回`、`撤回`、`视为撤回`。
- 重试 2 次仍失败：保持 `error` + `RETRYABLE:` 前缀推送，SaaS 记待补采。
- **不确定时归 error，禁止误判 not_granted**。

## 字段提取与翻译

### 案件级

| 契约字段 | 来源与处理 |
|---|---|
| `applyNo` | 输入值归一：大写 + 去空格/连字符/小数点，保留校验位（`202310000123.4 → 2023100001234`） |
| `name` | 详情页「发明名称」原文 |
| `applyDate` | 「申请日」→ `YYYY-MM-DD`（支持 `/`、`.`、中文年月日）；非法置空 |
| `legalStatus` | 法律状态中文 → 编码（下表）；表外文案 → `0` |
| `applicant` | 申请人列表用中文顿号 `、` 拼接为单字符串 |
| `caseStatus` | 案件状态原文，仅用于 not_granted 判定，不下发 |

### legalStatus 映射（表外文案一律 → 0 未知）

| 页面文案 | 编码 |
|---|---|
| 申请中（审中/实审/公开等） | 1 |
| 专利权维持 / 已授权 / 专利权有效 | 2 |
| 驳回 | 3 |
| 撤回 / 视为撤回 | 4 |
| 权利终止 / 专利权终止 / 失效 | 5 |
| 其他一切表外文案（含"主动放弃"） | 0 |

### patentType 推导（申请号左起第 5 位）

申请号结构为 `年份(4位) + 类型(1位) + 流水号 + 校验位`，**第 5 位数字即专利类型**：

| 第 5 位 | 含义 | 建议映射到 SaaS 编码 |
|---|---|---|
| `1` | 发明专利申请 | `INVENTION` |
| `2` | 实用新型专利申请 | `UTILITY_MODEL` |
| `3` | 外观设计专利申请 | `DESIGN` |
| `8` | PCT 发明专利申请（进入中国国家阶段） | `INVENTION` |
| `9` | PCT 实用新型专利申请（进入中国国家阶段） | `UTILITY_MODEL` |
| 其他 | 不识别 | **留空报错，不要猜** |

- 示例：`CN202320123456.7` → 归一后 `202320123456` → 第 5 位 `2` → `UTILITY_MODEL`。
- 本单 `2018111401422` → 第 5 位 `1` → `INVENTION`；与 seed 的 `fee_rule` 发明档（10-12年 4000 / 13-15年 6000 / 16-20年 8000）完全吻合，可作交叉校验。
- **先归一再取位**：去掉 `CN` 前缀、小数点、空格、连字符后，从第 1 位起数到第 5 位。
- 8/9 是 PCT 特例，归入发明/实用新型编码即可；但**年费年度口径不同**（PCT 进入中国国家阶段的年度自国际申请日起算），落库时以页面「申请日」为准，不要另行推算。
- 该字段**当前不在上报契约内**，客户端无从下发（详见 `data-schema.yaml` › `serverGap`）。本推导**由服务端在写库时执行**。

### 费用明细（fee item）

| 契约字段 | 来源与处理 |
|---|---|
| `factType` | 费用种类原文含「年费滞纳金」→3；等于「年费」→1；**其余种类（恢复费/复审费/请求费…）直接丢弃，不进批次** |
| `feeYear` | ①正则提取费用种类文案中的 `(第N年度)`/`第N年` → ②提取不到用 `dueDate` 相对 `applyDate` 反推（授权后首年年费在第2年缴，按年差推算）；**两级都失败 → 整笔丢弃，禁止 null** |
| `amount` | 去千分位/￥/¥/元/空格 → 数值（元，两位小数）；非法或 ≤0 或 >1000000 → 整笔丢弃 |
| `amountRaw` | 页面金额原文 |
| `dueDate` | → `YYYY-MM-DD`；非法/年份越界（1985 前、当前+20 后）置空，若置空导致 feeYear 兜底失败则整笔丢弃 |
| `feeStatus` | 未缴→`UNPAID`；缓缴→`DEFERRED`；减缴→`REDUCED`。**已缴清的整行丢弃**：`费足`（＝已缴费）、`已缴`、`已缴费` 等表示该年度已缴清的状态，已无应缴义务，属「已缴费」范畴，按交付边界不采集、不推送、**不计入对账失败项**（属正常丢弃，不是异常）。服务端只接受上述三个值（实测传 `UNKNOWN` 被 400 拒），**禁止把已缴清状态改写成 `UNPAID` 凑合**——那会凭空造出一条假催缴 |
| `dedupKey` | `"{applyNo}|{费用种类原文}|{dueDate}"`（applyNo 用归一后的值） |

去重：同案内 `(费用种类, dueDate, 金额)` 重复只留一条。

### 条数与排序规则（2026-10-10 起，已确认）

| 类型 | 来源表 | 筛选 | 排序 | 取几条 |
|---|---|---|---|---|
| 未缴年费 | 应缴费信息 | 年费类 + 状态可映射为 UNPAID/DEFERRED/REDUCED | **缴费截止日升序** | **前 2** |
| 已缴年费 | 已缴费信息 | 只同年费类（**不含**年费滞纳金） | **缴费日期降序** | **前 2** |

- **授权公告日**：搜索**结果列表行**里有（`授权公告日：YYYY-MM-DD`），随 patent 上报为 `grantDate`。
- **已缴费信息表没有「缴费截止日」列**（列序：费用种类 | 应缴金额 | 缴费日期 | 缴费人姓名 | 票据代码 | 票据号码）。
  已缴行 `lateDueDate` **留空**（严禁编造），排序与 `dedupKey` 用**缴费日期**。该口径已与用户确认。
- 被截断条数记入 `meta.truncated`，对账时如实说明。
- **已缴行附带凭证**：`voucherNo`（票据号码）与 `paidTime`（缴费日期）**均可入库**，都是服务端字段
  （采集端勿自造 `payDate`/`invoiceNo` 之类的别名）。
  **2026-10-13 起采集端也直接产出 `voucherNo`**，与上报契约同名、无需改名映射
  （`push_mcp.py` 仍兼容读改名前旧结果的 `invoiceNo`/`payDate`）。
  - ⚠️ **字段名一律以 `push_fee_batch` 的 DTO schema 为准，不要拿 `list_fee_ledgers` 的返回列名
    当上报字段名** —— 台账是平台计算引擎的**只读输出**（工具描述：「金额与状态由平台计算引擎维护，
    回传数据不影响清单」），其 `dueDate`/`payableAmount`/`lateFee` 由服务端按规则**自行推算**，
    与上报字段**不同源**。台账只适合验证「字段是否真正落库」。
  - ⚠️ 服务端对**已缴行幂等**：不覆盖已有的 `paidTime`。**验证字段能否写入必须用待缴行**（推 `PAID`），
    拿已缴行测会永远显示「没生效」——这是踩过的坑。
  - ⚠️ 改回 `UNPAID` 时服务端**只改 `status`，不清** `paidAmount`/`paidTime`/`voucherNo`，且**无法通过 MCP 清空**。
    别拿真实案件当字段试验的靶子。
- **「接受」≠「入库」**：DTO 没有的字段会被**静默忽略**。验证新字段必须推完回查台账。
- 单案费用条数上限 50，超出判整页误采，整案记 `error` + `RETRYABLE:应缴明细异常`。

## payload 构建与推送（Step 4）

采集脚本已直接产出 payload-ready 的 JSON（`<outdir>/<申请号>.json`），推送用 `push_mcp.py`：

```sh
$PY references/scripts/push_mcp.py --dir <采集结果目录> [--dry-run]
```

- 自动按 **10 条专利/批**切分；`queryStatus=ok` 的按「有应缴 / 无应缴」分别成批。
- **直连 MCP 端点**：工具调用层对数组参数的序列化有缺陷（`patents`/`fees` 一律报
  `must be array`，空数组也失败），故脚本走 `http://localhost:48080/open-api/mcp`；
  token 从 `~/.workbuddy/mcp.json` 内联读，不打印、不落盘。
- 对 **502/503/504 自动退避重试 4 次**（服务端零星抖动，不代表批次失败）。
- 产物：`_payload_NN.json`（可查）、`meta.json`（持久化 batchId）、`push_result.json`（回执）。

**关键约束**：

- **batchId 必须稳定**：重跑同一批数据要复用同一 `meta.json`，否则服务端当作新批次、**重复入库**。
- **分批（10 条专利/批）是为了隔离脏数据**：一条写库失败不拖垮整批。
- 推之前先核对三项：**专利数 / 费用条数 / 金额**，与采集阶段播报的累计值对齐。
- **「接受」≠「入库」**：DTO 里没有的字段会被**静默忽略**（不报错、不计 rejected）。
  新加字段务必推完回查 `list_fee_ledgers`。
- 对账报告用 `make_report.py --dir <目录> --list <清单> --out <报告.md>` 生成。
- 推送失败按 `troubleshooting.md` §5 分级处置；`rejected` 非空只补推被拒条目。
- 采集阶段的失败项（`not_found` / `not_granted` / `error`）由 `report.json` 汇总，**不要**把它们塞进 `fees` 凑数。

```
