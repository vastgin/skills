# 专利年费时时报

用户问一句「现在有什么要交的年费」，本技能把 SaaS 里**同一次**年费周报数据（与邮件预览同一份）
播报到终端 —— 不等周一推送、不登管理后台。

**只读**：本技能全程不写任何数据，也不触发推送。采集/上报走 `patent-fee-monitor` 技能，两者互不影响。

## 播报纪律（违反即失真）

- **`markdown` 字段原样输出**：不改列、不重排、不"美化"成自己的格式。
  它与管理后台「年费周报 › 邮件预览」的指标区和明细区同源，改写就失去了"看到什么就是什么"的意义。
- **截断必须明说**：`totalItems > shownItems` 时正文末尾有「共 N 条，仅显示前 M 条」，
  必须**逐字转述**，不要把前 M 条说成"全部"。
- **空态照实说**：正文只有「本期无 90 日内待缴明细」时，就说这一句，
  不要补"大概没有需要缴的费用"之类的解释扩张。
- **数字以工具返回为准**：用户只问某个数字（如"逾期几笔"）时，用结构化字段
  `totalPayable` / `buckets[]` 回答，**不要自己相加、不要估算**。
- **不缓存**：数据随服务端统一的「今天」滚动，不要跨会话复用上一次的结果。
- **不越界解读**：本技能只回答"有哪些、什么时候到期、多少钱"。
  要归因、要对比、要看分布 → 交给 `patent-fee-charts` 技能。

## 交付边界

**播报什么**

| 区块 | 内容 | 来源字段 |
|---|---|---|
| 标题与基准日 | 「年费周报 · 待缴与逾期概览」+ 数据截至日 | `dataDate` |
| 指标区 | 待缴年费总数 + 逾期年费 / 7日内到期 / 8-30日到期 / 31-90日到期 四档计数 | `totalPayable`、`buckets[]` |
| 明细区 | 截止日升序、只含 90 日内待缴、最多 20 行，7 列 | `markdown` 表格 |
| 截断提示 | 真实条数超过呈现条数时的一句话 | `totalItems` vs `shownItems` |

**不播报**：90 日以上（`OVER_90`）档 —— 远期行每周都在，是噪音不是"要动的事"（与邮件指标区同取舍）；
金额待录的行会显示「金额待录」，这是系统里确实没有金额，**不要用 0 或估算值代替**。

**明确不做**

- 不推送、不定时：本技能是 on-demand 的，不要替用户设置提醒或订周报。
- 不写回：不调用 `push_fee_batch`，不修改任何清单行。
- 不做筛选参数：不想按档位/国别二次筛选（保持与邮件预览逐块一致）；
  要看分布，用 `patent-fee-charts`。
- 不查 90 日以上的完整清单：需要全量请引导用户到管理后台「年费周报」页面。

## 红线（违反即停）

- **禁止编造数据**：工具返回什么就报什么；缺的空态、截断都如实说。
- **token 只存在于 `Authorization` 头**：禁止写入 git 跟踪的文件、日志、payload、对话正文。
  获取方式见 SaaS「MCP接入凭证」页面（**禁止让用户把 token 粘贴进对话**）。
- **工具名与语义以工具 schema 为准**：`get_fee_weekly_report`，无入参；不要臆造参数。
- **不把 `markdown` 当模板**：它是当次数据的快照，不是可复用的模板。
